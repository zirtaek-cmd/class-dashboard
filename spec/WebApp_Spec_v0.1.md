# 스마트칠판 학급 웹앱 — WebApp_Spec_v0.1

## 1. 개요
- **목적**: 각 반 스마트 칠판(안드로이드 크롬)에 상시 게시할 정보 대시보드 + 교사 알림 시스템
- **대상 반**: 11개 반
- **호스팅**: GitHub Pages (정적) + Firebase Firestore (실시간 데이터)
- **비용**: 전 항목 무료 티어로 운영 (GitHub Pages / Firebase Spark / NEIS Open API / 기상청 공공API)

## 2. 구조 (방식 B: 단일 웹앱)

```
class-dashboard/
  display/
    index.html      ← 반 선택(최초 1회) + 대시보드 표시 화면
    app.js           ← 공통 로직 (NEIS 연동, 날씨 연동, Firestore 구독)
  admin/
    index.html       ← 교사 공용 관리자 페이지 (공지 작성 + 학생 알림)
  firebase-config.js  ← Firebase 프로젝트 연결 설정
```

- 각 반 칠판은 동일한 `display/index.html` URL 접속
- 최초 접속 시 반 선택 화면 표시 → 선택 값(`classId`, 예: "1-3")을 `localStorage`에 저장
- 이후 재접속 시 저장된 `classId`로 자동 진입 (반 선택 화면 생략)
- 화면 구석에 "반 변경" 버튼으로 재설정 가능

## 3. 화면 레이아웃 (3칼럼, 개편)

| 왼쪽 | 가운데 | 오른쪽 |
|---|---|---|
| 날씨 + 시간/날짜 (통합 카드, 좌우 분할) | 공지사항 | 시간표 + 학사일정 (통합 카드, 좌우 분할) |
| 이미지 게시판 | 알림 팝업 (하단, 평소 숨김) | 급식 |

- **날씨+시간 통합 카드**: 카드 하나를 좌우로 분할, 왼쪽엔 날씨, 오른쪽엔 실시간 시계(1초~15초 주기 갱신)+날짜
- **시간표+학사일정 통합 카드**: 카드 하나를 좌우로 분할, 왼쪽엔 시간표(정규 시간표 대비 변경 과목은 빨간색 강조, 아래 10-1 참고), 오른쪽엔 학사일정
- **이미지 게시판**: 통합 카드로 확보한 공간에 신설 (아래 5-2 참고), 급식은 그 대신 오른쪽 칼럼으로 이동
- 가운데 칼럼: 담임 작성 정보(공지 + 알림)로 시선이 우선 가도록 배치, 시간/날짜가 위로 흡수되며 공지사항이 칼럼 전체 차지
- **지난 공지사항 영역 없음** — 별도의 과거 공지 표시 영역을 두지 않고, 그 공간만큼 "공지사항" 보드를 확장하여 사용
- **알림 발생 시 인터랙션 제한**: 미확인 알림이 있으면 화면 전체에 투명 오버레이가 깔려 다른 영역(시간표, 공지 등) 터치를 차단하고, 팝업 카드의 "확인" 버튼만 조작 가능. 확인 시 해당 카드만 닫히고 남은 미확인 알림이 있으면 오버레이 유지, 없으면 화면 정상 복귀
- 공지사항을 제외한 모든 보드 제목(날씨/시간/시간표/학사일정/게시판/급식)은 동일한 글자 크기·색상으로 통일

## 4. 데이터 소스

| 정보 | 출처 | 비고 |
|---|---|---|
| 급식 | NEIS Open API | 전교 공통, 캐싱 없이 매 로드 시 호출 |
| 학사일정 | NEIS Open API | 전교 공통 |
| 시간표 | NEIS Open API | `classId` 파라미터로 반별 분기, 정규 시간표(`data/regular-timetable.json`)와 비교하여 변경된 과목은 빨간색 표시 |
| 날씨 | 기상청 공공API 또는 OpenWeatherMap | 위치 고정, 1시간 주기 갱신 |
| 시간/날짜 | 브라우저 로컬 시계 | 실시간, API 불필요 |
| 공지사항 | Firestore (`notices`) | 교사 작성, 당일만 표시, 반/학년/전교 3단계 범위 |
| 알림 | Firestore (`calls`) | 담임 작성, 확인 시까지 표시 |
| 이미지 게시판 | Firestore (`boards`) | 교사 작성, 제목+이미지, 반/학년/전교 3단계 범위, 만료 없음(교사가 직접 삭제) |

## 5. Firestore 데이터 구조

```
# 반별 공지 (11개)
notices/{classId}  { text: string, date: "YYYY-MM-DD" }

# 학년 공지 (3개) — 신규
notices/grade-1, notices/grade-2, notices/grade-3  { text: string, date: "YYYY-MM-DD" }

# 전교 공지 (1개) — 신규
notices/all  { text: string, date: "YYYY-MM-DD" }

calls/class1/queue/{autoId}  { memo: string, timestamp, date: "YYYY-MM-DD" }
calls/class2/queue/{autoId}  ...
...
calls/class11/queue/{autoId}
```

- **반 구성**: 1학년 3개 반, 2학년 4개 반, 3학년 4개 반 (총 11개)
- **notices**: 대상마다 문서 1개씩 고정(반 11개 + 학년 3개 + 전교 1개 = 총 15개), 매번 덮어쓰는 구조 → 데이터 누적 없음
- **calls**: 반마다 서브컬렉션(`queue`)을 두어 **알림을 스택(여러 건 누적)으로 관리**
  - 알림 발생 시 `queue`에 새 문서 추가(자동 생성 ID)
  - display 페이지는 `queue`를 시간순으로 구독 → 미확인 알림이 여러 개면 카드 형태로 쌓여서 표시(최신이 위)
  - 확인(터치) 시 해당 문서만 삭제 → 쌓인 만큼만 존재, 확인되면 즉시 사라짐 → 장기적으로도 데이터 누적 없음
  - 자정 넘어 남아있는 미확인 알림(`date`가 오늘이 아님)은 display 페이지가 감지 시 자동 삭제(클라이언트에서 정리, 별도 서버 스케줄러 불필요)
- **공지 초기화 로직**: 서버 스케줄러 없이 "저장된 `date`가 오늘과 다르면 화면에서 숨김" 방식으로 클라이언트에서 판단 (무료 플랜 제약 회피)

## 5-1. 공지사항 범위 (반 / 학년 / 전교)

### 교사 페이지 UI
대상을 버튼 그리드로 배치하여 클릭 1회로 선택:

```
1학년   [1반] [2반] [3반]         [1학년 전체]
2학년   [1반] [2반] [3반] [4반]   [2학년 전체]
3학년   [1반] [2반] [3반] [4반]   [3학년 전체]
                [전교생]
```

- 선택된 버튼은 시각적으로 강조(색 반전 등)
- 선택된 대상을 입력창 위에 텍스트로 재확인 표시 (예: "2학년 전체(1·2·3·4반)에 게시됩니다")
- 대상 선택 시 **해당 대상에 오늘 작성된 공지를 입력창에 자동으로 불러옴**
- 교사는 기존 내용 아래 줄바꿈하여 추가 작성 → 저장 시 전체 갱신
- 수정/삭제는 기존과 동일한 방식(텍스트 편집 후 저장, 전체 삭제 시 내용 비우고 저장)

### display 페이지 표시 (공지사항 보드)
- 대시보드는 자기 반 + 자기 학년 + 전교, **3개 문서를 동시 구독**
- 각 문서에서 `date`가 오늘인 것만 선별하여 **하나의 공지 보드에 통합 표시**
- **정렬 순서**: 범위가 넓은 것부터 (전교 → 학년 → 반)
- **범위 라벨**: 전교 공지 → `[전체]`, 학년 공지 → `[2학년]` 등 학년 표기, 반 공지 → 라벨 없음
- 여러 줄 텍스트가 줄바꿈 그대로 보이도록 `white-space: pre-line` 적용

### 알림 기능
- **변경 없음** — 기존 반 단위 알림 구조 그대로 유지 (학년/전교 범위 개념 미적용)

## 5-2. 이미지 게시판

### 데이터 구조
```
boards/{targetId}/posts/{autoId}  { title: string, imageData: string(base64 data URL), date: "YYYY-MM-DD" }
```
- `targetId`는 공지사항과 동일한 체계(`{classId}`, `grade-N`, `all`)
- Firebase Storage는 2026년 정책 변경으로 무료(Spark) 플랜에서 제외되어 유료 전환 필요 → **이미지를 Base64로 인코딩해 Firestore 문서에 직접 저장**하는 방식으로 무료 유지
- 만료 없음(공지와 달리 자동 숨김 로직 미적용) — 교사가 직접 삭제할 때까지 계속 게시

### 업로드 시 이미지 처리 (클라이언트, 관리자 페이지)
1. 원본 이미지를 캔버스로 가로 최대 1000px로 리사이즈
2. JPEG 품질 70%로 압축 → 950KB(Firestore 문서 1MB 한도 대비 여유분) 초과 시 품질 50%, 30% 순으로 자동 재시도
3. 그래도 950KB를 넘으면 **업로드 차단** + 안내 문구 표시, 다른 이미지 선택 유도
4. 클립보드 붙여넣기(Ctrl+V, 캡처 직후) 지원 — 파일 선택 없이 캡처 후 곧바로 업로드 가능
5. 캡처(스크린샷) 기준 실측 용량은 대개 100KB 미만으로, 무료 한도(1GB) 대비 수천~수만 장 저장 가능한 수준

### 관리자 페이지 UI (2칼럼)
```
왼쪽                          오른쪽
대상 선택(반/학년/전교 버튼)     게시글 목록 관리
공지사항 작성                  (선택된 대상의 게시글만 필터링,
알림 보내기                    썸네일+제목+범위+삭제 버튼)
                              이미지 게시판 업로드
                              (제목+파일선택/Ctrl+V+게시 버튼)
```
- 왼쪽·오른쪽 칼럼 하단 정렬: "알림 보내기"가 기준, "이미지 게시판 업로드"가 그 높이에 맞춰짐 (중간 요소가 남는 공간을 유연하게 흡수)
- **대상 선택과 게시글 목록 연동**: 반/학년/전교 버튼을 누르면 게시글 목록도 그 대상의 게시글만 걸러서 표시 (공지사항의 "선택 시 기존 내용 불러오기"와 같은 패턴)
- 목록에서 각 게시글 삭제 가능(교사만)

### display 페이지 표시 (학생 화면)
- 자기 반 + 자기 학년 + 전교, 3개 대상의 게시글을 하나의 보드에 통합 표시 (공지사항과 동일한 통합 방식)
- 카드 구성: **제목 → 사진(썸네일)** 순서
- 카드 클릭 시 모달로 원본(리사이즈된) 크기로 확대, 배경 클릭 또는 닫기 버튼으로 닫힘
- 범위 라벨(`[전체]`/`[2학년]`)로 출처 구분, 반 게시글은 라벨 없음

## 5-3. 정규 시간표 비교 표시 (구현 완료)
- 교사가 제공한 정규 시간표를 `data/regular-timetable.json`에 저장 (반ID → 요일 → 교시 → 과목명 구조)
- NEIS 시간표 API로 받은 오늘의 실제 시간표와 대조하여, 정규 시간표와 다른 교시는 **글자를 빨간색으로 강조**
- 교시가 없는 시간(예: 1학년 7교시)도 빈 칸으로 표시(항상 1~7교시 칸 생성)
- 학기 변경 시 NEIS API의 `SEM` 파라미터 및 `data/regular-timetable.json` 내용을 갱신 필요

## 6. 알림(Call) 플로우

1. 담임 선생님이 관리자 페이지에서 반 선택 → 메모 입력 → 전송
2. `calls/{classId}/queue`에 새 문서 추가 (`memo`, `timestamp`, `date`)
3. 해당 반 display 페이지가 `queue`를 실시간 구독(`onSnapshot`) 중 → 변경 감지 즉시 가운데 칼럼 하단에 팝업 카드로 추가 표시
4. 확인 전 추가 알림이 오면 **카드가 위로 쌓이는 스택 형태**로 표시 (최신 알림이 맨 위)
5. 칠판에서 각 카드의 "확인" 터치 → 해당 문서만 삭제 → 그 카드만 사라지고 나머지는 유지
6. 알림은 **소리 없이 화면 팝업으로만** 표시

## 7. 인증 및 접근 통제

- **관리자 페이지**: Firebase Authentication + Google 로그인
- **도메인 제한**: `@ai.jne.kr` 계정만 로그인 허용 (외부인 차단)
- **학생 접근 방지**: 학생과 도메인이 동일하여 로그인 자체는 가능하지만, 관리자 페이지 URL은 학생에게 공유되지 않으므로 실질적 접근 경로 차단
- **권한 모델**: 로그인한 모든 교사는 11개 반 전체에 접근 가능 (반별 권한 분리 없음)
- 관리자 페이지에 `<meta name="robots" content="noindex">` 적용 (검색엔진 노출 방지)

## 8. Firestore 보안 규칙 (요지)

- `notices/{targetId}` 문서 (`{classId}`, `grade-N`, `all` 모두 포함):
  - **읽기**: 누구나 가능(display 페이지는 자기 반 + 자기 학년 + 전교, 3개 문서만 구독)
  - **쓰기**: 인증된 사용자(`@ai.jne.kr` 도메인 Google 로그인, 교사)만 가능
- `calls/{classId}/queue/{callId}` 문서:
  - **생성(쓰기)**: `@ai.jne.kr` 도메인 Google 로그인(교사)만 가능
  - **읽기**: 누구나 가능(display 페이지는 자기 `classId` 하위 `queue`만 구독)
  - **삭제(확인 처리)**: display 페이지가 백그라운드에서 **Firebase Anonymous Auth**로 자동 로그인 → 해당 익명 세션은 **자기 `classId` 큐의 문서 삭제만** 허용 (그 외 쓰기/타 반 접근 불가)
- `boards/{targetId}/posts/{postId}` 문서:
  - **읽기**: 누구나 가능(display 페이지는 자기 반+학년+전교 3개 대상만 구독)
  - **생성/삭제**: `@ai.jne.kr` 도메인 Google 로그인(교사)만 가능
- 시간표/급식/날씨는 Firestore에 저장하지 않고 API 직접 호출 → 별도 보안 규칙 불필요

## 9. 개인정보 보호 원칙

- 알림/공지 메모에 포함되는 실명 등 개인정보는 **당일 한정, 최소 보관**
- 알림 확인 완료 시 메모 내용 초기화 (이력 미보관)
- 별도 로그/히스토리 컬렉션 없음 → 유출 표면적 최소화

## 10. 운영 관련 유의사항

- 안드로이드 크롬 절전모드 대비: 자정 기준 자동 리로드 로직 필요 (공지/알림 날짜 초기화와도 자연스럽게 연동)
- 소리 알림 없음 → 화면 시각적 강조(팝업 오버레이/색상 강조)로만 처리
- 날씨 API는 기상청 공공API 대신 **OpenWeatherMap** 사용 권장 (기상청 API는 브라우저 직접 호출 시 CORS 이슈 발생 가능, OpenWeatherMap은 CORS 지원)
- **GitHub 저장소는 무료 플랜 특성상 Public(공개)**으로 운영됨 — 코드(관리자 페이지 구조 포함)는 누구나 열람 가능하나, 실제 기능은 Firebase 인증·규칙으로 보호되므로 코드 공개 자체는 기능적 위험이 낮음(인지 후 진행 확정)
- API 키(NEIS, OpenWeatherMap) 및 Firebase 설정값은 정적 사이트 구조상 클라이언트 코드에 노출됨 — NEIS/날씨 키는 공공 무료 API라 문제 없고, Firebase 설정값은 보안 규칙이 실제 방어선이므로 노출 자체는 정상 범주

## 11. 구현 단계 (Phase)

**Phase 1 — 계정·키 준비 (코딩 전 선행)**
1. NEIS Open API 인증키 발급/확인
2. OpenWeatherMap 무료 API 키 발급
3. Firebase 프로젝트 생성 → Firestore 활성화, Authentication에서 **Google 로그인** + **Anonymous 로그인** 둘 다 활성화
4. GitHub 저장소 생성(`class-dashboard`, Public)

**Phase 2 — display 정보 표시부 (Firestore 연동 전, 눈에 보이는 결과물부터)**
- 반 선택 화면 + `localStorage` 저장 로직
- NEIS 급식/학사일정/시간표 연동 및 3칼럼 레이아웃 배치
- 날씨(OpenWeatherMap) 연동

**Phase 3 — Firestore 연동 (공지·알림)**
- `notices`, `calls/queue` 구조 구현
- 보안 규칙 작성 및 적용(Google 로그인 vs Anonymous 권한 분리)
- display 페이지 Anonymous Auth 자동 로그인 처리

**Phase 4 — 관리자 페이지**
- Google 로그인(도메인 제한) 구현
- 반 선택 + 공지 작성 + 알림 전송 UI

**Phase 6 — 이미지 게시판 (신규)**
- `boards/{targetId}/posts` 구조 및 보안 규칙 추가
- 관리자: 업로드 폼(리사이즈/압축/용량 초과 차단 로직) + 대상별 게시글 목록 관리(필터링+삭제)
- display: 3개 대상 구독 통합 표시(제목→사진 순), 클릭 확대 모달
- 레이아웃 개편: 날씨+시간 통합, 시간표+학사일정 통합, 급식 이동, 게시판 신설

**Phase 5 — 운영 안정화**
- 자정 자동 리로드 로직
- 스타일링(Pretendard, 모노크롬 베이스 등 기존 디자인 원칙 적용)
